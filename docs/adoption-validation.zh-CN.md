# 真实新用户验证

[English worksheet](adoption-validation.md) · [文档目录](README.zh-CN.md)

状态：**等待真实用户试用**。自动化演练和 Agent 审查用于工程验证，不能证明真实用户
是否容易上手、是否愿意采用或再次使用。

请三名从未使用本项目的开发者，在没有维护者指导的情况下按照 README 试用。
使用可丢弃的 Git 项目，不使用生产仓库；参与者可以选择平时使用的 Agent，
只使用终端也能提供有价值的观察。

## 试用任务

1. 安装运行时，完成第一次通过验收并登记完成的流程。
2. 在自己的临时项目中，为一个小任务添加验收条件。
3. 在检查通过后修改代码，并解释报告为何发生变化。
4. 根据交接文件启动新 Agent 会话，判断下一步应该做什么。

## 每位参与者的记录

为每位参与者复制下表。只记录实际观察，尚未尝试的项目保留“未采集”。

| 观察项 | 结果 |
| --- | --- |
| 操作系统、Python 版本、使用的 Agent 或终端 | 未采集 |
| 具体发行标签或开发提交；使用的文档语言 | 未采集 |
| 从开始到第一次有效完成的耗时 | 未采集 |
| 需要求助或手工修复 JSON 的步骤 | 未采集 |
| 能否解释命令证据与浏览器／人工声明的区别 | 未采集 |
| 能否解释过期证据为何不能用于完成任务 | 未采集 |
| 意外拒绝或错误放行的情况 | 未采集 |
| 是否愿意再次使用；保留参与者自己的理由 | 未采集 |

验收目标：三人都能在维护者不介入的情况下完成第一项流程，并正确解释证据过期报告。
将失败记为需要改进的发现，不归咎为“用户操作错误”。在增加集成或编排功能前，
优先解决重复出现的卡点。

## 参与者信息

未经参与者同意，不收集密钥、源码、截图或遥测。运行时没有自动遥测功能。
本次实现没有联系任何参与者，也没有产生真实用户试用结果。
